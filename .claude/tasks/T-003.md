# T-003 — SMART discovery + CapabilityStatement FHIR

## Estado: ⬜ pending
## Fase: 1 — Infra
## Agente: —
## Prioridad: alta

## Descripción
Exponer los endpoints de descubrimiento que el frontend (MedplumClient) y clientes FHIR externos necesitan para autoconfigurar la conexión: el CapabilityStatement y el SMART configuration.

## Archivos a crear

| Archivo | Rol |
|---|---|
| `backend/app/fhir/capability.py` | Router con `GET /fhir/R4/metadata` → CapabilityStatement |
| `backend/app/core/smart_config.py` | `GET /.well-known/smart-configuration` → SMART discovery JSON |

## Criterio de aceptación

- [ ] `GET /fhir/R4/metadata` retorna JSON con `resourceType: "CapabilityStatement"` y `status: "active"`
- [ ] `GET /.well-known/smart-configuration` retorna JSON con `authorization_endpoint`, `token_endpoint`, `scopes_supported`
- [ ] Ambos endpoints sin autenticación (públicos)
- [ ] `Content-Type: application/fhir+json` en `/fhir/R4/metadata`
- [ ] MedplumClient puede descubrir la URL del servidor apuntando al VPS

## Estructura mínima del CapabilityStatement

```json
{
  "resourceType": "CapabilityStatement",
  "status": "active",
  "fhirVersion": "4.0.1",
  "format": ["application/fhir+json"],
  "rest": [{
    "mode": "server",
    "security": {
      "extension": [{"url": "http://fhir-registry.smarthealthit.org/StructureDefinition/capabilities",
                     "valueCode": "launch-standalone"}]
    },
    "resource": [...]
  }]
}
```

## Estructura mínima del SMART config

```json
{
  "authorization_endpoint": "/oauth/authorize",
  "token_endpoint": "/oauth/token",
  "token_endpoint_auth_methods": ["client_secret_basic"],
  "scopes_supported": ["openid", "profile", "launch", "patient/*.read", "user/*.read"],
  "response_types_supported": ["code"],
  "code_challenge_methods_supported": ["S256"]
}
```
