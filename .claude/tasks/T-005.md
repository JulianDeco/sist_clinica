# T-005 — FHIR R4: recursos core (Patient, Practitioner, Coverage)

## Estado: ⬜ pendiente
## Fase: 2 — Core clínico FHIR
## Agente: —
## Prioridad: alta

## Descripción

Implementar en Spring Boot los endpoints FHIR R4 de los recursos core:
`/fhir/R4/Patient`, `/fhir/R4/Practitioner` y `/fhir/R4/Coverage`
(CRUD + search params básicos). Es la base de datos clínica sobre la que
se construyen agenda (T-006, CU-01) e historia clínica (T-007, CU-02).

> **Brief de tarea — no es el spec.** Per SDD, antes de codificar se debe
> escribir `docs/specifications/T-005-fhir-core.spec.md` (template
> `_template.spec.md`) y obtenerlo APPROVED. Reglas de negocio, AC y edge
> cases se definen ahí — no adivinar.

## Lineamientos arquitectónicos (decididos por ADR)

- **Storage JSONB** (ADR-009): recursos en `fhir_resources.resource_data`
  + search params extraídos en `fhir_search_params` — nunca buscar con
  full-scan sobre el JSONB.
- **Multitenant row-level** (ADR-003): toda query incluye `tenant_id`
  (TenantContextFilter + TenantAwareRepository).
- **Validación FHIR R4** en capa de aplicación (el schema no la garantiza).
- Responses con `Content-Type: application/fhir+json`; endpoints
  `/fhir/R4/{ResourceType}` con mayúscula inicial.

## Dependencia ADR-015 (vínculo Usuario ↔ Practitioner)

ADR-015 (PROPOSED) agrega `user_tenants.practitioner_fhir_id`: el vínculo
se asigna **en esta tarea**, cuando nace el recurso `Practitioner`.
Incluye la migración Flyway correspondiente (siguiente número disponible) y
la validación en use case de que el id apunte a un `Practitioner` del mismo
tenant (no hay FK física).
