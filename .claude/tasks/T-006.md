## Descripción
Endpoints CRUD para que el super_admin gestione roles, permisos y asignaciones de usuario sin tocar la BD directamente.

## Archivos a crear

| Archivo | Rol |
|---|---|
| `backend/app/modules/rbac/router.py` | Endpoints `/admin/roles/*` y `/admin/users/*/roles` |
| `backend/app/modules/rbac/service.py` | Lógica: crear rol, asignar permiso, invalidar cache |
| `backend/app/modules/rbac/schemas.py` | Pydantic schemas para request/response |

## API a implementar

| Endpoint | Método | Descripción |
|---|---|---|
| `/admin/roles` | GET | Listar todos los roles con sus permisos |
| `/admin/roles` | POST | Crear rol nuevo |
| `/admin/roles/{id}` | PUT | Editar nombre/descripción de rol |
| `/admin/roles/{id}` | DELETE | Eliminar rol (no permitir roles base) |
| `/admin/roles/{id}/permissions` | POST | Asignar permiso a rol |
| `/admin/roles/{id}/permissions` | DELETE | Quitar permiso de rol |
| `/admin/users/{id}/roles` | GET | Ver roles del usuario |
| `/admin/users/{id}/roles` | POST | Asignar rol a usuario |
| `/admin/users/{id}/roles` | DELETE | Quitar rol de usuario |

## Criterio de aceptación

- [ ] Todos los endpoints requieren `require_permission("role", "write")`
- [ ] No se pueden eliminar roles base (`super_admin`, `medico`, `recepcionista`)
- [ ] Al asignar/quitar rol → `invalidate_permissions_cache(user_id)` ejecutado
- [ ] Al asignar/quitar permiso a rol → invalida cache de **todos los usuarios** con ese rol
- [ ] Respuestas incluyen los permisos actualizados (no requiere segundo GET)
